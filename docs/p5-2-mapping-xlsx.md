# P5.2 offline mapping XLSX

Issue #10. **Картирование → Журнал → Выгрузка → Формат файла → Excel (.xlsx)** creates one `FieldForge-Mapping.xlsx` through the native iOS Share Sheet / Files. CSV remains the default and keeps its existing 14 files and manifest contract. Switching format keeps the same frozen preview. Changing selection still invalidates preview.

## Shared data contract

`FieldForge-Mapping-XLSX/1` consumes `MappingCSVExport` directly. Despite that historical type name, it owns immutable typed values, not CSV strings. There is no second selection engine or CSV-to-XLSX conversion. Every table/column, including exact timestamp companion fields, has the same name/order/value as the [P5.1 contract](p5-1-mapping-csv.md). Sheet order follows that snapshot: `Сводка`, `projects`, `horizons`, `excavations`, `excavation_horizons`, `plans`, `points`, `photo_point_contexts`, `measurements`, `joint_sets`, `interpretation_evidence`, `tectonic_structures`, `assessments`, `photos`, `photo_attachments`.

The summary records format/export ID, project and optional scopes, inclusive dates, Gregorian calendar/timezone, actual half-open UTC boundaries, snapshot/export timestamp, all 14 table counts and completeness counts. It documents units, source/north/coordinates, current versus historical context, stored Q, input-only RMR, precision, privacy and analysis-versus-backup limits. Completeness counts identify points lacking XY/Z/measurements, structures with incomplete orientation, Q without a result, photos without capture time and unknown draft-capture locations. These are counts of missing data, not engineering risk ratings. Names and canonical UUIDs identify optional scope; an empty selection can still show its selected scope UUID.

All current points occur once by stable UUID with effective revision/version. Original measurements, raw diagnostics, original orientation strings, evidence links, coordinate units/CRS/plan version, stored Barton inputs/evaluation and all photo metadata retain the P5.1 policy. Photo context rows are historical linkage only. No source records, persistence schema, journal history, algorithms, DXF or image bytes change. Original file availability remains explicitly **not checked**; missing originals do not remove registers. This is an analysis output, not a complete backup or an application-specific DIPS import profile.

## Cell types, precision and safety

- Text is an OOXML inline string, including formula-like text and original leading apostrophes. No CSV escaping apostrophe is added. UUIDs, original decimal inputs, enums, nested JSON and ISO UTC timestamp strings stay text. ISO UTC preserves timezone meaning; exact companion seconds preserve the stored Date beyond millisecond display.
- Finite Double values whose shortest round-trip decimal significand needs at most 15 digits are numeric cells. Values requiring more digits are that exact decimal string in a text cell. Trailing significand zeros do not count as significant. Subnormal Doubles are text because Excel cannot represent them numerically. Integers with more than 15 decimal digits are text. No approximate helper columns are created. Thus a numeric analysis column may contain both number and exact-text cells; consumers must parse text deliberately for higher-precision analysis.
- Absent numbers/timestamps and `.empty` are blank cells, never fabricated zero. Empty source strings remain explicit empty text. Stored Q results are copied, never evaluated. Numeric/display values are not rounded.
- XML metacharacters are escaped. SpreadsheetML `_xHHHH_` sequences and XML-invalid control characters use ST_Xstring escaping, including CR to avoid XML newline normalization. No formula, macro, hyperlink, external relationship or external workbook part is emitted. No EXIF is opened.
- Excel limits (1,048,576 rows including header, 16,384 columns, 32,767 UTF-16 code units per text cell) and ZIP32's less-than-4-GiB archive limit cause a recoverable error, never truncation. Nonfinite numbers are rejected. CSV or a smaller date period remains available. Detailed JSON may exceed the text-cell limit for unusually large records.

## Package and presentation

Dependency-free Foundation writer, OOXML Transitional (ECMA-376 / ISO/IEC 29500), store-method ZIP32. Internal part names only. A worksheet per data table, workbook and package relationships, content types, styles, core/extended metadata. CRC-32, UTF-8 ZIP flag, streaming data descriptors and central directory follow [PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT). See Microsoft [worksheet structure](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-sheets) and [inline strings](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.inlinestring). No third-party runtime library or license dependency is added.

Dark graphite headers with white bold text, restrained alternating pale rows, wrapped text, top alignment, ID/date/JSON-aware widths, frozen first row and autofilter on all 14 data sheets, including empty sheets. No merged data cells. Canonical English headers support engineering tools; the Russian summary explains names/units/limitations. General numeric format avoids presentation rounding; long JSON/notes can be expanded in the spreadsheet application.

The ZIP writer streams XML fragments directly to its export-owned temporary file, so it does not assemble the complete workbook in memory. The existing frozen dataset is still held in memory. Generation runs off the main actor. Cancellation is checked during parts/rows/writes. Failure removes only the newly created UUID directory; success keeps the file through share dismissal. Repeated export recreates a deterministic workbook from the same preview in a different owned directory. No broad cache deletion or source-file mutation occurs. OS reclamation handles abandoned temporary exports after process termination.
