# Regulatory Excel observations in Mapping

Open **Журнал → Импорт Excel**, choose a regulatory workbook, review the counts, and import. Use **Открыть журнал** after the commit. Choose the same project and dataset name for later editions. The initial name comes from the filename when there is no workbook binding or uniquely recognized prior import. Select the dataset's north reference on the import screen. Its default applies to newly imported rows, and a correction can declare a different reference for one observation. The Data columns share one declared reference per observation. Original compass readings, numeric azimuths and prior declarations remain in source history. Settings supplies the initial reference for new manual entries, joint interpretations, and tectonic orientations. Core Motion and wedge heading use the reference reported by their capture method. There is no declination or convergence conversion.

Production rows with missing spatial metadata import at project scope. Review the invalid row list before committing. Conflicts need a field-level decision. An invalid row and all rows sharing an ambiguous source ID are excluded from the transaction. Existing native Exchange and bound regulatory workbook handling continue to use the saved UUID and revision baseline.

The journal uses a read projection over effective native revisions and source observations. A source record keeps its project/dataset/source key, UUID, immutable raw XYZ spelling, Excel SHA-256, source row, and append-only revisions. Source evidence is neither copied into a native row nor given artificial field dates or chainage. Date filters operate on known field observation dates. Dataset and assignment filters locate imported observations. Select the visible group or individual rows in the journal to apply an assignment. Excavation-only edits preserve the horizon, matching evidence, and original XYZ. Source geology uses the project lithology picker and existing field categories and limits. ROCK is an exact string and is exported as text. The existing review for numeric Excel cells can resolve legacy native codes against the project catalog.

## Confirming a dataset on a plan

Under **Координаты набора и правила DXF**, select the immutable DXF revision and confirm its XY coordinate reference, axes, and units against the dataset. Confirmation is scoped to the dataset, plan UUID, SHA-256, and horizon. It can be used to display a point even when there is no verified vertical association. Both plan and dataset use the same XY drawing coordinates with no coordinate transformation. Incompatible declared metadata, an archived plan, or missing XY prevents display. The observation detail explains the reason. Project and plan management keep referenced revisions available for historical evidence. Source versions from older journals with recorded DXF matches already carry evidence for their matched plan.

For geometry matching, explicitly confirm the common vertical datum and enter the maximum XY distance and Z difference in metres. There are no default tolerances. Set each tolerance using the verified survey and the positional meaning of the plan lines for that project. The limits govern which features qualify for association and are not estimates of measurement accuracy. The source Z column is in metres. The plan Z conversion uses its verified metres or millimetres declaration.

## Automatic assignment

1. Keep the saved horizon and explicit manual decisions. If a later source edit changes the coordinates relevant to a DXF or elevation match, retain the horizon and link to prior matching evidence in the version history.
2. Search confirmed DXF plans with the shared 3D geometry index. Test the Euclidean XY distance to the closest point on each eligible straight segment and interpolate the segment Z at that XY parameter. Apply both inclusive limits. A single distinct horizon across qualifying plan revisions is a match. Multiple horizons are ambiguous. An excavation is suggested only if every qualifying plan carries the same explicit excavation link. A missing or unreadable configured geometry file can prevent a unique result.
3. With no DXF candidate and a verified common vertical datum, test inclusive horizon elevation ranges. Assign the horizon only if exactly one range contains source Z. The nominal horizon elevation does not define a range.
4. Keep remaining records at project scope with a reason. Use **Повторить поиск горизонтов** from the journal after configuring additional verified plans or intervals. Manual clearing is an explicit decision and is preserved. The version details show the matched plan revision and tolerances, projected segment elevation and distances where available, or the verified range.

The closest-point calculation reuses FieldForge's existing WCS segment projection, documented with independent controls in [DXF elevation plan revisions](dxf-elevation-plan-revisions.md#supported-elevation-geometry). See Christer Ericson, *Real-Time Collision Detection* (2005), §5.1.2, and the [AutoCAD 2024 DXF LINE specification](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-FCEF5726-53AE-4C43-B4EA-C84EB8686A66.htm) for WCS endpoints.

Dataset setup and additional version evidence use optional schema-8 fields. The offline backup stores the journal and referenced DXF originals. The regulatory XLSX is an edit surface with row bindings, while the offline backup carries the complete destinations, matching rules and version history. Clone/reimport behavior uses the original source key and three-way reconciliation.

The repository's DXF fixtures are synthetic local surveys. Matching them establishes behavior against known inputs. Real workbook import and real-project spatial qualification are separate checks.
